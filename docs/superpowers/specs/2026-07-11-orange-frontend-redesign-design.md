# Orange 前端重构设计

日期：2026-07-11
状态：设计方向已确认，等待实施计划评审

## 1. 目标

Orange 是面向项目、合同与回款管理的 Wails 桌面应用。本次重构以“漂亮且实用”为首要目标，在不牺牲高频操作效率的前提下，建立具有独立开发者作品辨识度的视觉体验。

设计记忆点：**有鲜明橙色人格的未来感独立桌面应用。**

整体比例：

- 80% 克制、可靠、高效的桌面生产力工具。
- 20% 集中的未来感视觉时刻。

视觉概念命名为 **Ember Orbit / 熔橙轨道**。

## 2. 核心原则

1. 视觉效果必须服务信息层级与操作反馈，不做无意义的常驻动画。
2. 品牌橙是注意力资源，只用于当前状态、主操作和关键数据。
3. 玻璃是功能层材质，用于导航、浮层和临时控件；内容面板以稳定、近不透明的表面为主。
4. 深色与亮色都是完整主题，不采用简单颜色反相。
5. 所有动画必须支持 `prefers-reduced-motion`，且不能阻塞操作。
6. 先统一设计系统和应用骨架，再逐页重构，避免继续堆积全局 CSS 补丁。

## 3. 应用骨架

### 3.1 顶部悬浮导航

移除当前左侧栏，改为窗口顶部的悬浮玻璃岛。

导航分为三段：

- 左侧：Orange Logo 与产品名称。
- 中间：工作台、项目管理、收款日历、数据分析。
- 右侧：全局搜索或命令入口、通知、设置、用户菜单。

系统设置从主导航移出，使用右侧齿轮入口。当前页面采用实心橙色胶囊状态，其他页面仅在悬停和键盘聚焦时出现柔和高光。

顶部栏兼任 Wails 无边框窗口标题栏：

- Logo 周围、导航两侧和控件之间的空白区域允许拖动窗口。
- 导航、按钮、搜索、通知、设置和用户菜单必须标记为不可拖动。
- 双击可拖动区域遵循平台窗口最大化或还原行为。
- 页面滚动后顶部栏提高不透明度并轻微收紧高度，不改变导航位置。

窄屏布局中，中间导航转为底部 Dock；顶部只保留品牌、页面标题和必要操作。

### 3.2 页面空间

- 内容最大宽度应可根据窗口宽度扩展，不沿用侧边栏占位。
- 顶部导航与窗口边缘保留明确呼吸空间。
- 页面使用统一的横向内边距和垂直节奏。
- 背景空间光只存在于应用级环境层，不逐卡重复计算鼠标位置。

## 4. 仪表盘设计

仪表盘作为整套重构的视觉样板页，采用“电影感财务 Hero”。

### 4.1 Hero

Hero 回答三个问题：

1. 当前最重要的财务状态是什么？
2. 最近的风险或机会是什么？
3. 用户下一步应该做什么？

建议内容：

- 主指标：本月预计回款。
- 辅助说明：与上期比较和下一笔款项到期时间。
- 风险摘要：逾期金额或高风险项目。
- 唯一主操作：处理待收款或查看回款计划。

橙色轨道、光源和折射效果集中在 Hero。视觉效果不得影响文字对比度或形成持续的阅读区运动。

### 4.2 数据层级

Hero 下方显示三项辅助指标：

- 已结算金额。
- 待结算金额。
- 平均回款天数或逾期风险。

中部采用主次两栏：

- 主栏：现金流趋势，支持周、月、季度和年度切换。
- 次栏：未来七天待处理事项，直接进入对应项目或款项。

底部承载最近项目、异常与逾期、最近活动。所有列表项都应提供明确下一步，而非仅展示数据。

### 4.3 图表

- 灰阶构成基线与历史数据。
- 品牌橙只表示选中数据、当前周期或关键风险焦点。
- Tooltip 使用近不透明浮层，避免多重玻璃叠加。
- 数据切换保持坐标系稳定，优先更新数值和路径，避免整个图表重新飞入。

## 5. 双主题

默认主题策略为跟随操作系统，同时允许用户明确选择亮色、深色或自动。

### 5.1 Night Orbit

- 背景：深炭黑与暖黑，不使用纯黑。
- 表面：低透明深色玻璃与近不透明数据面板。
- 光线：单一暖橙环境光，避免多色霓虹。
- 阴影：以边缘高光、内阴影和低透明投影塑造层次。

### 5.2 Day Ember

- 背景：暖象牙白和浅沙色，不使用冷白大底。
- 表面：纸张或陶瓷质感的近不透明面板。
- Hero：日光橙渐变与较高对比的白色内容。
- 阴影：柔和暖灰投影和细边框，不复制深色主题的发光效果。

### 5.3 共享令牌

两套主题共享：

- 字体层级。
- 间距与圆角。
- 品牌橙和语义状态色。
- 组件尺寸与交互状态。
- 动效时长和缓动曲线。

主题切换使用约 220ms 的颜色与透明度溶解，不进行大范围位移和缩放。

## 6. 动效语言

动效分为四级：

- 即时反馈：120–180ms，用于按钮、开关、选中与悬停。
- 局部过渡：180–240ms，用于菜单、筛选器、Tooltip 和内容展开。
- 页面过渡：240–320ms，以透明度和小幅纵向位移为主。
- Hero 时刻：最长 400–500ms，只在首次进入或关键业务完成时使用。

规则：

- 高频操作越频繁，动画越短、越克制。
- 常驻动画全页面最多一个低对比环境层。
- 卡片悬停最多提升 1–2px，并显示边缘高光。
- 数字更新可以平滑过渡，但不得逐位长时间滚动。
- reduced-motion 下取消环境运动、视差和大范围变形，以淡入、颜色变化和静态高光替代。

## 7. 视觉系统治理

当前 `main.css` 与 `liquid-glass.css` 体积大且存在同名规则覆盖。实施前应建立单一设计令牌来源，并按职责拆分样式：

- `tokens`：颜色、字体、间距、圆角、阴影和动效。
- `foundations`：reset、排版、焦点、滚动条和可访问性。
- `layout`：应用骨架、顶部栏、内容容器和响应式规则。
- `components`：按钮、卡片、表单、表格、浮层和反馈组件。
- `motion`：关键帧、过渡和 reduced-motion。
- 页面样式：与对应 React 页面或组件放在一起。

禁止继续通过扩大单一全局 CSS 文件修复局部页面。

## 8. 性能与可访问性

- 移除每次鼠标移动时遍历全部玻璃卡片并读取布局信息的实现。
- 应用级环境光使用单一事件监听和 `requestAnimationFrame` 节流。
- 局部高光仅在确有价值的交互组件内部实现。
- 动画优先使用 `transform` 和 `opacity`。
- 自定义按钮和图标必须提供键盘焦点、`aria-label` 和足够命中区域。
- 模态框支持焦点捕获、Escape 关闭和关闭后焦点恢复。
- 状态不得只依赖颜色，必须同时使用文字或图标。

## 9. 状态与错误体验

仪表盘及后续页面统一提供：

- 与最终布局一致的骨架屏。
- 有下一步建议的空状态。
- 局部数据失败与整页失败的区别处理。
- 数据刷新过程保持已有内容，避免整页闪烁。
- 操作成功使用短促、可撤销或可继续的反馈，不使用长时间庆祝动画。

## 10. 实施顺序

1. 统一设计令牌并拆分样式架构。
2. 重构应用骨架和可拖动顶部导航。
3. 完成仪表盘 Hero、数据面板、现金流图表和待处理事项。
4. 完成双主题和全局主题切换。
5. 统一加载、空状态、错误状态、键盘操作和 reduced-motion。
6. 将样板系统扩展至项目列表与详情。
7. 扩展至日历、分析、表单和设置页面。
8. 最后加入经过性能验证的折射、轨道背景和关键完成动效。

## 11. 非目标

- 不改变后端业务模型和 API 合同，除非实现阶段发现仪表盘缺少必要聚合数据。
- 不引入大面积 3D 场景、无限粒子或与任务无关的装饰动画。
- 不追求与参考图片逐像素一致。
- 不在第一阶段同时重写所有页面。
- 不让每个组件拥有独立的玻璃和光效逻辑。

## 12. 验收标准

- 侧边栏完全替换为顶部悬浮导航，窗口拖拽和所有控件交互无冲突。
- 仪表盘首屏在五秒内清晰传达主要回款状态、风险和下一步操作。
- 深色与亮色均具备完整、协调且有辨识度的主题表现。
- 页面不存在持续干扰阅读的动画，reduced-motion 行为完整。
- 常用窗口尺寸下无横向溢出，窄屏导航可以正常转换。
- 主题切换、页面切换和图表交互保持流畅。
- 新样式遵循统一令牌，核心组件不再依赖重复全局覆盖。
